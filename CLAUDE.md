# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

An interactive website styled like a Sierra point-and-click scene: a park bench, bulletin board, and pay phone on a pole, with mountains behind. The sky, light, shadows, and weather mirror the real time and weather in Missoula, Montana. The vibe (quiet, liminal, slightly nostalgic) matters more than features. Art direction is hi-res *shaded* pixel art with visible pixels and dithering, not chunky low-res and not painterly smooth gradients.

**Beauty over realism.** Everything should pop: blue sky through gaps in the clouds, sparkle on wet grass and dew, bright stars, bold sunset color. Live data (Open-Meteo now, webcams later) tells the scene *what is happening* (ceiling, snowline, fog, rain) and never what color things are. Do not sample palettes from camera frames, and do not let overcast or rain flatten the image into webcam gray. When adding an effect, "is it more beautiful?" comes before "is it accurate?".

## Commands

- `npm run dev` — serves the site at http://127.0.0.1:5173 via `tools/serve.py` (static, with no-cache headers so a plain reload picks up edits). `npm run lan` serves the same on 0.0.0.0:5174 for other devices (reached as http://liminal.bench on the home network via a router DNS entry and a Windows port forward). No build step, no bundler, no framework; everything is native ES modules loaded by `index.html`.
- `for f in $(find src -name '*.js'); do node --check "$f"; done` — the only automated check. There are no tests or linters.
- `python3 tools/build_backdrop.py [--art NAME] [--debug DIR] [--scale N]` — regenerates `assets/backdrop.png`, `assets/backdrop_mask.png` and `assets/backdrop.json` from a painting and its config `art/NAME.json` (which files: the scene with props, the same scene without them, optionally the props alone on black; the traced silhouettes, prop boxes, cork, hotspots, camera targets, fog lines, snow caps, default notes). `art/current` names the painting in use. Needs Pillow + numpy. Run it after changing the art or its config; `--debug` writes mask overlays to look at; `--scale N` upsamples to test a bigger scene.
- Visual verification: with the dev server running, `node tools/screenshot.mjs out.png "<js to run on the page first>"` renders the scene at its native size in headless Chromium (software rasterization, so frame timings there are several times worse than on a real GPU; the worker-rendered terrain needs a few seconds to land, which the tool waits for) (needs `npm install` and `npx playwright install chromium` once). Use the debug panel's inputs from the JS argument to preview conditions, e.g. set `#dbg-enabled` checked, `#dbg-hour`, `#dbg-month`, `#dbg-weather`, then dispatch an `input` event on each. Then look at the PNG. This is how rendering changes get checked.

## Architecture

**One environment object drives everything.** `src/main.js` runs the `requestAnimationFrame` loop. Each frame `computeEnv()` builds `state.env` from the current time (or the debug override), the sun/moon position (`src/util/solar.js`), the live weather (`src/weather.js`, Open-Meteo, no API key, refreshed every 10 min), and the sky palette (`src/palette.js`, keyframed by sun altitude and modified by cloud cover, precipitation, fog). Renderers read only `env`; they never fetch or look at the clock. Missoula local time is derived via `Intl` with `America/Denver`; `src/state.js` holds the constants (`W`, `H`, `HORIZON`, lat/lon).

**The scene is the painting, re-lit per frame-key.** The canvas is the size of the art (`assets/backdrop.json`, read by `src/state.js` as `META` at load; the canvas element and CSS stage follow it, and all scene geometry the JS needs, hotspots, cork, lantern, camera targets, fog lines, snow caps, default notes, comes from that JSON, so JS holds no art-specific numbers and a new painting is a new `art/NAME.json`). `assets/backdrop.png` is the current scene (`art/current`, config `art/layered.json`): two of the user's paintings at 2752x1536 layered by the build, `dean_stone_alone_transparent_sky.jpg` at the back (Mount Dean Stone's forested dome) and `mount_sentinel_alone_transparent_sky.jpg` in front (Sentinel's slope, trees, meadow, with its sky flattened to a checkerboard that the build keys out; `front` in the config), so each mountain is masked against its own sky and a cloud on one can never leak; the bench, board, pay phone and pole are copied in from `wider_aspect.png` through the props-only mask, `props_from` in the config) at native pixels, with the sky masked out and the painted notes cleared off the cork; `assets/backdrop_mask.png` carries per pixel a depth layer (R: sky, peak, range, far hill, flank, trees, near), a material (G: grass, foliage, rock, snow, dirt, shrub, prop) and a height-within-layer (B). Prop pixels come from the props-only image on black when the config has one, else from the difference between the painting with props and the same painting without them, inside known boxes (`prop_rects` in the config). A config with `front` composites a front painting over the back one (optionally pixel-doubled, never resampled) and makes the far layer whatever of the back shows above it. A config with `far_is_forest` treats the far range as a forested dome (layer RANGE, canopy snow) rather than rock; `scan_simple` finds the crest from hillside and forest colors only, so clouds lying on the ridge are not mistaken for it. `src/assets.js` decodes both once at startup; `src/render/terrain.js` walks every pixel and applies seasonal grass tint, the snowline (by height fraction per layer), rain darkening, aerial perspective/fog toward `pal.horizon`, then the **light**: each layer has a sun horizon for its top and one for its base (`LAYERS` in terrain.js; Missoula is a valley, so the meadow loses the sun at about +4.5° while Dean Stone's crest glows until about -2.6°), and the shadow line climbs each hill by height fraction as the sun drops. Lit surfaces take the alpenglow as **warm light**, a multiply by the light's tint plus a little added brightness, so a forest stays a warm dark green and grass goes orange (blending every color toward one gold flattened the scene to beige); unlit ground sits in blue sky-shadow; moonlight (night, moon up, bright phase) silvers snow and rock; silhouettes against the sky get a warm rim at low sun or a silver rim under the moon; then the ambient multiplier. Prop pixels skip tint and snow but get the same light. Two fog looks are drawn in the same pass: an **inversion** (`env.inversion`: fog code in a cold month, or the debug preset) fills the far valley behind the tree band with a flat-topped, lit-edged sea of fog (`INVERSION_TOP` in terrain.js, screen y) so the ranges rise out of it under a clear sky, and **mountain fog** (`env.mountainFog`: Open-Meteo low cloud cover, precipitation, or the debug preset) hangs noise-driven banks mid-slope on the peak, range and Sentinel's far end. An **overnight dusting** (`env.dusting`: snowfall in the last 18 hours from the hourly feed, and hours above freezing since; the debug preset derives the thaw from the hour of day) whitens the hills thinly and melts off from the bottom up at each layer's own `meltHours`, so by afternoon only the top of the range keeps it. The moon, inversion, mountain fog and dusting are part of `terrainKey`. The debug panel has a moon override (live / full / half / down) and weather presets for inversion and mountain fog. Sky pixels stay transparent so the procedural sky shows through. The painted summit snow is treated as a June amount: months with less (July through October per `SEASON_SNOW`) recolor those pixels as rock, and only snow beyond the painted amount is added. Live data still only decides *what happens* (snow, fog, wet); colors come from the painting and the palette. Silhouette keypoints and prop boxes live in the painting's config; material rules in `tools/build_backdrop.py`. **Do not redraw the props in code, and do not synthesize new art** (no tiled-texture fills, no invented ridgelines): the user's painting is the look; the build script only masks, classifies and cleans what is painted, and code only adds light, weather and what changes. If a silhouette is wrong, the user repaints it in `art/` and the config's traces get re-measured.

**Layers with cache keys.** `src/render/renderer.js` keeps offscreen canvases for the sky gradient, the re-lit terrain, the props, and the ambient-tinted props, each refreshed only when its key string in `env` changes (`skyKey`, `terrainKey`, `ambientKey`, plus the props key); those keys quantize sun altitude, cloud cover, snow, month, moon, fog, etc. If you add a new input to one of those renderers, add it to the matching key or the change will never show up. The two per-pixel passes (sky gradient, terrain) run in a **Web Worker** (`src/render/terrain_worker.js`, which imports the same modules; `state.js` and `assets.js` are worker-safe) and come back as an `ImageBitmap`, so a rebuild that takes a second on a big painting never stalls the page; the previous image stays up until the new one lands. From those, two static composites are built per key change: `base` (sky, moon, sun, terrain, fog bands, shadows, props) and `fg` (the same without the sky). Each frame draws straight onto the visible canvas under the camera transform: base, stars, clouds, then `fg` back over the clouds if there are any, lamp glow, precipitation. **Idle frames are skipped entirely** (nothing animated and no key change), which is what makes a 2752-wide scene affordable. Per-frame things are pre-rendered where they can be: the star field into its own layer ten times a second, rain and snow as two scrolling tiles per condition, the lamp glow as two additive sprites, each cumulus as a sprite. `window.__liminal` exposes `state` and `renderer`; set `renderer.profile = true` and read `renderer.steps` for per-step timings.

**Pixel discipline.** Everything is drawn with integer `fillRect`s, `fillCircle`, `plotLine`/`plotWire`, and Bayer dither patterns from `src/util/pixel.js`. No canvas `arc`, `lineTo` strokes, gradients, or `globalAlpha` on fills (they anti-alias). Colors are quantized with `quant`/`quantRGB` using the Bayer threshold so banding dithers. The scene faces south: sun azimuth 90..270 maps to screen x left..right (`skyXY` in `sky.js`), so `sunSide` (+1 east, -1 west) decides which way shadows fall. The painting itself is lit from screen-right (afternoon); that baked lighting does not change with the sun.

**Clouds.** `src/render/clouds.js` builds each cumulus once as a seeded cauliflower of hemispherical puffs (base row, one tower, two generations of smaller puffs on the upper arcs), turns that into a height field, and shades it toward the sun with five flat tones from the palette plus a rim tone for silhouette pixels facing the light, darker toward the flat base and in the creases between lobes, with Bayer dither only at tone boundaries. `cloudTones` handles the drama: tops take the sun color at low sun, undersides blaze ember-orange when the sun is at or just below the horizon, purple-gray well after dusk, silver tops under a bright moon. The sprite is cached per cloud and rebuilt when the tone key or light direction changes; `weatherfx.js` owns the cloud field (count from cover, wind advection, depth for size and haze).

**Props and lighting.** `src/render/props.js` takes where the painted bench, board, pay phone and pole are from `META` (`PROPS`/`HOTSPOTS`: hit rectangles, shadow footprints, labels; `CORK`; `LAMP`) and draws only what changes on top of them into one canvas: the notes pinned to the cork, snow caps, and, on the frame, the sun shadows and the lantern's night glow. The renderer multiplies that canvas by `env.pal.ambient` (multiply then `destination-in` to keep alpha) so notes darken at night without redrawing. It is redrawn only when `sunSide`, `groundSnow`, or `state.notesVersion` changes; bump `notesVersion` after mutating `state.notes`.

**UI.** `src/ui.js` owns hover captions, click-to-zoom (`VIEWS` gives each view a camera target and a panel dock side), the HTML panels (`PANELS` map, currently placeholder text), the debug panel (press `D`), and the status line. The canvas is CSS-scaled to the window via the `--s` custom property; all UI sizes are multiples of it.
