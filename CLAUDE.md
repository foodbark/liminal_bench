# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

An interactive website styled like a Sierra point-and-click scene: a park bench, a bulletin board, a pay phone, a utility pole with a lantern, and Missoula's mountains behind (Mount Sentinel on the left, Mount Dean Stone's forested dome in the middle distance). The sky, light, shadows, and weather mirror the real time and weather in Missoula, Montana. The vibe (quiet, liminal, slightly nostalgic) matters more than features. Hi-res *shaded* pixel art with visible pixels and dithering, not chunky low-res and not painterly gradients.

Three rules that override everything else:

- **Beauty over realism.** Everything should pop: blue sky through cloud gaps, sparkle on wet grass, bright stars, bold sunset color. Live data tells the scene *what is happening* (ceiling, snowline, fog, rain) and never what color things are. Do not let overcast or rain flatten the image to gray. "Is it more beautiful?" comes before "is it accurate?".
- **The user's paintings are the look. Never draw or synthesize art.** No code-drawn props, no tiled-texture fills, no invented ridgelines, no "smart" upscaling. The build script only masks, classifies, and cleans what is painted; code only adds light, weather, and what changes. If a silhouette or a mountain is wrong, the user repaints it (their art comes from Gemini) and the config's traces get re-measured. Dean Stone is the user's favorite mountain: check it first after any mask or lighting change.
- **`master` is production.** Cloudflare Pages redeploys https://liminalbench.net/ on every push (and GitHub Pages still redeploys the older https://foodbark.github.io/liminal_bench/ until it is retired), so master should always be a state you would show. The board at liminalbench.net is shared and public: never post test notes there.

**Hauntology is the mood.** "Liminal" here is meant in Mark Fisher's sense: a place that feels remembered more than seen, with the medium's wear left showing. Boards of Canada is the muse: warm, sun-faded, slightly detuned, beautiful first and worn second. The digital decay that `tools/pixelate.py` produces from the user's photos (flattened ramps, a snapped palette, lost fine detail) is part of the look, so do not tune it all away. Keep an artifact that reads as memory; fix one that reads as a broken image (blotchy dither, a swallowed silhouette, a subject that stops being recognizable). Never add fake decay: no scanlines, VHS overlays or glitch filters. The loss comes only from the conversion itself, and it stays in service of the beauty rule. The live sky is the counterweight: a remembered place under tonight's actual weather and stars.

## Commands

- `npm run dev` serves the site at http://127.0.0.1:5173 via `tools/serve.py` (static, no-cache headers). `npm run lan` serves 0.0.0.0:5174 for other devices on the home network (reached as http://liminal.bench through a router DNS entry and a Windows port forward). No build step, bundler, or framework; everything is native ES modules from `index.html`.
- `for f in $(find src -name '*.js'); do node --check "$f"; done` is the only automated check. No tests, no linter.
- `python3 tools/build_backdrop.py [--art NAME] [--debug DIR] [--scale N]` regenerates `assets/` from the painting named in `art/current` (Pillow + numpy). Run it after touching any painting or its config (it also cuts the paraglider wings from `art/paragliders.png` into `assets/glider.png`). `--debug DIR` writes mask overlays (sky magenta, layers tinted, props cyan) that you must look at. A full-size build takes about a minute.
- `python3 tools/pixelate.py PHOTO OUT.png --as mountain|trees|prop|photo [--size WxH | --width W] [--pixel N] [--flatten N] [--hues N] [--steps N] [--ink K] [--dither K] [--pop K] [--matte r,g,b]` turns a photograph into shaded pixel art, for the move from generated paintings to the user's own photos. It only averages, grades, flattens and palette-snaps the photo's own pixels: representation first, then beauty (crop never stretch, rare colors protected), and the drawn lo-fi feel comes from flat shapes and short hue ramps, not bigger pixels. `--as` sets the starting values per subject (far slopes dither and take no ink; foreground trees and props are inked and undithered; props are barely flattened so thin parts survive). The presets were tuned on stand-in photos, so re-judge them on each real one. Write the result into `art/` and the build takes it from there like any painting.
- `python3 tools/swap_flank.py CUTOUT --scale S --dy DY` puts a photographed Mount Sentinel into the painted front in place of the painted flank (keys the cut-out by color, shaves the halo off its edge, pixelates it as a mountain, lays it at the fit, clears the painted flank where the photo does not reach so the back shows). The bridging step while the scene is part photo, part painting; `art/layered_photo.json` is the config that uses its output. Rebuild after it.
- `node tools/screenshot.mjs out.png "<js run on the page first>"` renders the scene at native size in headless Chromium (`npm install` and `npx playwright install chromium` once). Drive the debug panel from the JS: set `#dbg-enabled` checked and `#dbg-hour`, `#dbg-month`, `#dbg-weather` (`live clear partly overcast rain snow fog inversion dusting mountainfog storm`), `#dbg-cover`, `#dbg-moon` (`live full half none`), `#dbg-peaks` (`live bare first winter`, the snow on the peaks), `#dbg-gliders` (`live up none`, paragliders off Sentinel), dispatching an `input` event on each. `?debug` in the URL opens the panel without the D key. The tool waits several seconds for the worker-rendered terrain. Then read the PNG. This is how every rendering change gets checked; headless is software-rasterized, so frame timings there are several times worse than a real GPU.
- `window.__liminal` exposes `state` and `renderer` on the page; set `renderer.profile = true` and read `renderer.steps` for per-step frame timings.

## Architecture

**One environment object drives everything.** `src/main.js` runs the `requestAnimationFrame` loop. Each frame `computeEnv()` builds `state.env` from the time (or the debug override), the sun and moon (`src/util/solar.js`), the live weather (`src/weather.js`: Open-Meteo, no key, every 10 minutes, current conditions plus the hourly feed for the past day), and the sky palette (`src/palette.js`, keyframed by sun altitude, modified by cover, precipitation, fog). Derived conditions live here too: `inversion` (fog in a cold month), `mountainFog` (low cloud cover or precipitation), `dusting` (snowfall in the last 18 hours and hours above freezing since). Renderers read only `env`.

**Snow on the peaks is data, not calendar.** `weather.js` also queries Open-Meteo lapsed to Dean Stone's summit (`RIDGE` in `state.js`, elevation 2050 m). `src/season.js` latches the first real accumulation up there (5 cm of model snow depth held for the last half day, `heldDepth`: the model wobbles by a centimetre or two hour to hour, and one hour of 2 cm once whitened bare peaks) in localStorage for one snow year; until it fires, September through December are held at bare no matter what `SEASON_SNOW` says, and after it the table gives the depth (floored at a white crest) and the spring melt, with the live held depth (5 cm and up) holding snow through warm spells. Never put the arrival back in the table. The debug `peaks` select forces any state.

**The scene is the user's painting, re-lit.** The canvas is the size of the art (phones and screens under 1100 CSS px wide get the half-size copy in `assets/small/`, written by the same build; `?small` / `?full` override; `SMALL` in `state.js`, passed to the worker through its URL). `assets/backdrop.json` (read by `src/state.js` as `META` at load) carries the size, horizon, hotspots, cork rectangle, lantern position, camera targets, fog lines, snow caps, and default notes, so the JS holds no art-specific numbers. `assets/backdrop.png` is the painting at native pixels with the sky masked out and the painted notes cleared off the cork; `assets/backdrop_mask.png` carries per pixel a depth layer (R: sky, peak, range, far hill, flank, trees, near), a material (G: grass, foliage, rock, snow, dirt, shrub, prop), and a height fraction within the layer (B). The layer and material codes are stored 32 apart in the PNG and snapped back on load: some browsers (Android Chrome among them) color-manage a PNG on its way into a canvas and shift values by a unit, which once turned every mask code into garbage on phones and one desktop. Sky pixels stay transparent so the procedural sky shows through.

**Paintings and configs.** Each painting has `art/NAME.json`; `art/current` names the one in use (currently `layered`). A config names the files (`art`, the prop-less `bare`, optionally `props_only` on black and `props_from` to copy prop pixels from another painting of the same scene, optionally a `front` painting layered over the back with its checkerboard "transparency" keyed out and pixel-doubled if it came at half size), the traced silhouettes (`skyline`, `peak`, `far_mid`, `meadow`), prop boxes, material flags (`far_is_forest`, `scan_simple`, `haze_scale`), and everything that ends up in `backdrop.json`. Coordinates are in the config's `ref` size; a painting that is an exact multiple of it scales automatically, one a few pixels off is snapped. Silhouette traces were partly measured and partly hand-placed; when a new painting arrives, re-measure rather than reuse.

**Terrain re-lighting** (`src/render/terrain.js`, per pixel): seasonal grass tint relative to the painting's September, snow by height fraction per layer (the painted summit snow counts as a June amount; July through October recolor it as rock), the overnight dusting melting bottom-up at each layer's `meltHours`, rain darkening, aerial perspective toward the sky's horizon color, then the light:

- Each layer in `LAYERS` has a sun horizon for its top and one for its base. Missoula is a valley, so the meadow loses the sun near +4.5° while Dean Stone's crest glows past -2.6°, and the shadow line climbs each hill by height fraction as the sun drops. Mount Sentinel is backlit at dawn: shadowed face, burning outline.
- Alpenglow is applied as **warm light**: a multiply by the light's tint plus a little added brightness, so a forest stays a warm dark green and grass goes orange. Blending every color toward one gold flattened the whole scene to beige once; do not go back to that. After direct sun leaves a mountain face the glow still washes it as scattered light (`afterglow`), while the valley sits in blue sky-shadow.
- A rim of light marks every silhouette against anything farther (sky or a layer behind): warm at dusk, silver under the moon, faint and pale by day. This is what keeps the ridges reading as separate planes; without it the scene goes flat.
- Moonlight silvers snow and rock at night. Inversion fog fills the far valley behind the trees with a flat-topped, lit-edged sea; mountain fog hangs noise-driven banks on the slopes and over the ridgelines.
- Prop pixels skip tint and snow but get the same light. The painting's own baked lighting (from screen-right) does not change with the sun.

**Compositing and cost** (`src/render/renderer.js`). The sky gradient and the terrain pass run in a Web Worker (`src/render/terrain_worker.js`; `state.js` and `assets.js` are worker-safe) and return an `ImageBitmap`; the previous image stays up until the new one lands. If the worker errors or never reports ready within 20 s (older browsers: no module workers, no top-level await in workers, no `OffscreenCanvas`), the same passes run synchronously on the main thread; `?noworker` in the URL forces that path for testing. The painting is drawn unlit the moment assets load so the scene is never empty while the first pass runs (it takes seconds on a big painting, far longer on phones); the status line says "lighting the scene…" until then, and `?diag` overlays the loading stages, errors and user agent so a failing device can report without dev tools. Both are refreshed only when their key string changes (`skyKey`, `terrainKey`, `ambientKey`, the props key). **If you add an input to one of those passes, add it to the matching key or the change will never show.** From them, `base` (sky, moon, sun, terrain, fog bands, shadows, props) and `fg` (the same without sky) are composited per key change; each frame draws straight to the visible canvas under the camera transform: base, stars, clouds, `fg` back over the clouds, lamp glow, precipitation. Idle frames are skipped entirely, which is what makes a 2752-wide scene affordable. Stars are re-drawn into their own layer ten times a second, rain and snow are scrolling tiles, the lamp glow is two additive sprites, each cumulus a cached sprite.

**Shooting stars.** `weatherfx.js` spawns a meteor every minute or two on dark clear nights (bright head, solid near tail, dithered far tail, under a second), more around the showers in `SHOWERS` (Quadrantids, Lyrids, Eta Aquariids, Perseids, Orionids, Leonids, Geminids), radiating from the shower's radiant when it is in the south-facing sky; `fx.meteor(env)` spawns one and `m.hold` freezes it for screenshots.

**Paragliders** (`src/render/gliders.js`). On a fair day with a light wind into the face, wings work Mount Sentinel's ridge, winter included. There is no feed for who is in the air, so like the dusting they are inferred from the weather (`gliderChance`: sun up and the day past mid-morning, dry, no low cloud, wind under about 10 mph from the west or southwest; more through the afternoon). The wings are the user's photo (`art/paragliders.png`): the build cuts the three that were up that day from it, each its own colors, keys out the sky and writes `assets/glider.png` and `META.glider` (the crest they soar along and how far above it they fly, from the config's `gliders`). Each flight picks a sail color (a short list in `SAILS`, some keeping the photo's own): the canopy's light and shade from the photo are laid over the sail, the pilot left alone, the way the moon keeps the painting's maria under a new color. They are used at the photo's own size, about 22 px wide, two or three times what a wing would truly subtend here, since a true-scale wing was a speck that vanished against the grass; the moon is cheated the same way. Each glider keeps one wing for its whole flight, flips to lean into its heading, soars a slow beat along the crest with a breathing of height, drifts with the wind, now and then glides out over the valley (`air.outX`) and back, and sinks behind the ridge when its time is up or the weather turns. The renderer draws the wings after the clouds and the foreground, then lays `near` (the foreground masked to the flank, trees, near and prop pixels) back over them, so a sail flies in front of Dean Stone and behind Sentinel, the trees and the props; the `crest` polyline is the near planes' skyline, the floor the wings stay above. One to three at a time, minutes apart. Hovering one gets a caption; the debug `gliders` select forces them up or grounds them.

**Stars.** `assets/stars.json` is the Yale Bright Star Catalog down to magnitude 5.2 (ra, dec, mag, spectral class; built once from a public mirror). `drawStars` in `sky.js` projects it for Missoula by local sidereal time (`env.lst`, from `siderealDeg` in `solar.js`) through `skyXY`, so the constellations are where they really are that night in the south-facing view; sizes scale with the scene, tints follow spectral class, faint stars drop out under a bright moon, and the layer redraws ten times a second. Twinkle follows one model (README, "How a star should twinkle"): each star has a spread, smoothed in time, that smears its light over a bigger patch (larger, dimmer per pixel) or a smaller one (sharp, bright) with the total held, mostly calm with a rare glint; a bright star's points swing between upright and diagonal; a glint low over the ridge flashes red or blue; the faintest stars and the planets are steady. Size and tone must never move independently, and nothing shrinks below its resting size: every version that did read as stars blinking out. The five naked-eye planets come from `src/util/planets.js` (JPL mean orbital elements, a Kepler solve, Earth subtracted, tilted to equatorial; a fraction of a degree, no feed) and are drawn in the same star layer: steady, never twinkling, sized by brightness (Venus and Jupiter bigger than any star), Mars tinted, hidden by the ridges and sheets like the stars; `planetSpots` carries their screen positions for the hover caption, and the debug info lists what is up. The brightest named stars (`NAMED` in `sky.js`, matched to the catalog by position at load) get the same hover caption through `starSpots`. The Milky Way is drawn in the sky-gradient pass (worker) as a dithered band along the galactic equator (`galacticLat`, `altAzToRaDec`), mottled with dark rifts, on dark clear nights only; sidereal time is in `skyKey` at night.

**Sun and moon.** `skyXY` in `sky.js` maps azimuth 90..270 to screen x and altitude to y with the ridge line (half the horizon height) standing for 8° and the top of the frame about 58°, since Missoula's hills sit about 8° above the valley; anything lower is behind the mountains, so sunrise and sunset happen behind the ridges and the disc is visible from roughly 9° up. `drawSun` is a solid disc, always, with a corona graded out through dither rings; the cloud sheets in front of it do the hiding. Never dither the disc, it reads as a checkerboard (the user asked for a solid disk twice). The moon is the user's painted disc (`assets/moon.png`, from `art/pixel_moon.png`) scaled to the scene with the unlit part of the phase cut away, recolored to white with gray maria (the rabbit should be visible); it dims behind veils and hides behind sheets (`env.sky`), while cumulus simply draw in front of it; at night a moon that is up becomes the clouds' light source (`drawClouds` picks the moon's position for the light direction) and clouds near it glow silver at their edges (`cloudTones` takes a `moonNear` factor); both swell a little near the ridge (the moon to 1.4x; 2x was too big) and the moon gets a faint dithered halo only under a cirrostratus or altostratus veil or in fog (ice and haze make halos; a clear night shows the bare disc). Debug moon option `low` puts a full moon just over the ridge.

**Pixel discipline.** Integer `fillRect`s, `fillCircle`, `plotLine`/`plotWire`, and Bayer dither patterns from `src/util/pixel.js`. No canvas `arc`, stroked paths, gradients, or `globalAlpha` on fills (they anti-alias). Colors are quantized with `quantRGB` against the Bayer threshold so banding dithers. Procedural sizes scale with `SCALE` (canvas width over 1024). The scene faces south, so `sunSide` (azimuth east or west of 180) decides which way shadows fall.

**Sky.** Open-Meteo reports low, mid and high cloud cover separately. `computeEnv` weights them into `cond.shade` (low counts fully, mid most of the way, high a quarter), and that, not the total, is what grays the palette, dims the sun's glow and disc and holds back the alpenglow: a cirrostratus sunset is the sky going pink end to end, not an overcast, and once flattened the whole scene to gray mud (the status line calls it "high overcast"). The raw total still hides what a veil does hide: stars, the Milky Way, meteors, moonlight. The bands also become `env.sky`: thin high cover is cirrus, thick high cover a cirrostratus veil; mid cover is altocumulus fields or an altostratus veil; low cover is fair-weather cumulus, a lumpy stratocumulus sheet as it closes up, flat stratus in fog, dark nimbostratus under precipitation; a storm adds one cumulonimbus (a six-lobe tower with an anvil streaming downwind, kept apart from the cumulus field, moving fast the way valley storms do, its base hung over the ranges) over a broken nimbostratus sheet, with lightning every few seconds: a jagged branched bolt from the cell's base to the ridge (glow, body, core) plus a faint frame-wide flash; `renderer.fx.strike(true)` holds one for screenshots. The sheet types (`src/render/sheets.js`) are drawn once into an ImageData in the worker (job `sheets`, key `sheetKey`) with a cloud-deck perspective (depth grows toward `VANISH`, 62% of the horizon: rows get smaller, flatter, denser, hazier) and periodic in screen x (the wrap blend runs in x even where the noise is sampled in perspective-compressed coordinates, or the two copies mismatch at the seam), then scrolled with the wind on the page between the sky and the cumulus (slowly: the drift of sheets and cumulus is a fraction of a pixel per second per mph of wind; at 0.4 per mph the field whizzed past on a 19 mph evening). Cumulus (`src/render/clouds.js`) are sprites: a seeded cauliflower of hemispherical puffs (base row, three-lobe tower, three generations of small puffs that scallop the outline); the max of the hemispheres gives the silhouette, a blurred copy the shading normals so the body reads as one soft mass; small puffs get a bright cap, a shadow crease and a lit lip; five flat tones (cream, warm mid, lavender, purple) plus a rim tone and almost no dither, after the user's reference clouds; `cloudTones` gives sun-colored tops at low sun, ember undersides at sunset, purple-gray after dusk, silver under the moon, and the same tones color the sheets. A third of the cumulus are small flat far rows placed above where the mountains hide the cloud horizon. `weatherfx.js` owns the cumulus field and precipitation.

**Notes on the board** (`src/notes.js`). The config's note slots are filled by default notes; what people pin (the compose form on the board panel, one line, 80 characters) takes the most faded slots, ages from its posting time (two weeks to fade, gone at sixteen days), and is stored in localStorage unless the page is served with the notes API: `notes.js` probes `api/notes` at load and switches to the shared board where it answers. Anyone can tear any note down, the way a real board works (the user's call: someone may take everything down, that's just life): on the board's close-up the notes can be pointed at (`closeupNotes` gives their rectangles in canvas pixels; the caption names the one under the pointer) and a click on one offers to tear it down; a posted note goes for good, one of the painting's default notes leaves bare cork and comes back after a note's life, as if someone put up a fresh flyer, and a fresh pin takes a bare slot first. The API is `functions/api/notes.js`, a Cloudflare Pages Function over D1 (`db/schema.sql`: the `notes` table and `torn`, which records tearings for the limit and which default notes are down; binding in `wrangler.toml`), rate-limited per address and in total for pinning and, loosely, for tearing (six an hour per address: a person can clear the board, a script cannot keep it bare). `?v=2` on the API returns `{ notes, torn, posters }`; the bare path still returns the plain array for pages holding the older script. `docs/deploy.md` has the deploy steps.

**Posters** (`src/pixelate.js`, `functions/api/posters.js`). The pin form also takes a picture from the device. It is turned into pixel art in the browser before it goes anywhere: `pixelate.js` is the port of `tools/pixelate.py` (box-average onto the art grid, pop, the edge-keeping flatten, hue-family ramps, palette snap, ink on strong edges; the `prop` preset), cropping to the nearest of three poster sizes (`POSTER_SIZES`: 160x212 tall, 212x160 wide, 176x176), under a second on a laptop. The original never leaves the browser; the server gets the small PNG the page made (base64 in the `posters` table, a few tens of kilobytes, 48 KB and 224 px caps checked from the PNG header; twenty an hour per address, sixty an hour in all, loose by the user's call, tearing down being the moderation) and serves it back by id from `posters/[id].js` with a hard cache. Posters share the notes' slots in posting order and age and blow away with them; past the slots, older posters pile up beneath the newest, each a little askew (`under`), up to `PILE` (24) on the board, while an old text note simply blows away. A poster comes in one of three sizes chosen on the pin form, a handbill, a flyer or a big sheet (`k`, 1 to 3, its picture at that many close-up pixels per art pixel, stored with the poster; the form pre-chooses one the way the board would, and a poster with no choice gets one from its id in `posterBox`; on the half-size build the scale is halved, since it is set in the full build's close-up pixels and came out twice as big against the board on phones), its box on its slot's center and held inside the cork, so a big one spills over its neighbors; it is its picture with a thin white border sized in screen pixels (`screenPx`: sized in canvas pixels it vanished on small screens) that yellows with age, the paper cut to it: on the scene averaged down to its box, on the close-up laid at its own whole-number scale so its pixels stay square. Clicking one on the close-up holds it up (`state.poster`): the second zoom, drawn by `drawPosterView` over everything with the frame dimmed by a dither, its panel offering to tear it down; any click puts it back. Browser-only mode keeps posters in localStorage as data URLs. Everything network-facing is relative to the page, so the site can live at a path prefix or a domain root.

**The pay phone** (`src/phone.js`, the panel in `ui.js`). Click the phone: the receiver lifts and there is a dial tone. Dial on the keypad (or the keyboard), or pick a number from the phone book, which dials it. `assets/audio/numbers.json` is the directory: the book, a map of numbers to outcomes (`time`: the real time and temperature from the scene's clock and feed; `machine`: an answering machine whose greeting plays and then takes a message through `functions/api/voicemail.js` and the `voicemail` D1 table, the board's twin with the same limits; `recording`: a file; `intercept`; `busy`, with an optional `text`: the bench's listing is the pay phone's own line and gets this for now), and the intercepts' lines. An unlisted number in the listed exchange (`exchange`, 555) is "not in service"; one in any other exchange, or too short, "cannot be completed as dialed" (the book's crossed-out "home" listing dials into that one); seven digits dial locally (`area`, 406). An entry with a `file` plays it from `assets/audio/`; a file that is missing falls back to the transcript and the tones carry the call, so every number works before any voice is recorded. The international line is the AT&T operator menu of February 2002 (`att_menu_2002.mp3`, `sit: false`: a routing, no tones in front); the two intercepts and the phone company's number are Jane Barbe herself (`barbe_cannot.mp3`, `barbe_service.mp3`, cut from Telephone World's compilation; `barbe.mp3` is the whole compilation, her interview at the end). `requires` names an item the caller must carry, or a list where any one opens the line (`src/items.js`, localStorage; nothing hands them out yet: `?give=whistle` in the URL or `window.__liminal.items.give('bluebox')` does for testing, `?drop=whistle` or `?drop=all` takes things back; the phone panel lists what the caller carries under the book), or the call gets its `locked` intercept; `opens` gives an item's own sound and line when it opens a call (the whistle, `whistle.mp3`; with `interrupt`, the call first starts down the locked road, the operator menu, and the item cuts it off mid-word a few seconds in) and `coin` the coin tones the phone answers with (a quarter's five quick beeps, from `Sounds.coin`); `ring` picks the ringback (`us`, `eu`, `uk`). The tones (dial, touch tones, the three-tone SIT, ringback, busy, reorder, the beep, the coin tones, the off-hook howler that follows the operator menu, `after: howler`) are made in `Sounds` with the Web Audio API: signals, not art. Nothing sounds until the receiver is lifted. The phone's view stands the phone large on the left third of the frame (`views.phone` in the config, 2.3x) and the panel takes the right half (`#panel.phone`: the keypad beside the phone book, the line's words above, the message field below, sized so nothing scrolls; a narrow window falls back to the plain box). The panel's hang up puts the receiver on the hook and stays at the phone (the button turns to pick up; a key or a book entry lifts it too); step back, a click on the scene or Escape leaves, which hangs up. The intercepts' and the time line's voice is meant to be Jane Barbe's, from a collector's recording (README, "The pay phone's voice"); the keypad moves onto the phone's close-up painting when that art arrives.

**Close-ups.** A prop can have a second painting for its zoomed view: `closeups` in the config names the file (the prop alone on black, at the scene's size; the board's is `art/blank_board.jpg`) and its cork rectangle. The build keys the black to alpha and writes `assets/ID_closeup.png` (halved into `assets/small/`), and `META.closeups` carries the file and cork. When a zoom settles on that view `ui.js` sets `state.closeup`, and the renderer lays the close-up over the zoomed scene (after the lamp glow, before precipitation), multiplied by the props' ambient lifted almost halfway to full so the paper stays readable at night. `drawCloseupNotes` re-sets the board's notes on the big cork: the scene's slots stretched onto the close-up's cork, the paper scaled uniformly, the text set for real in VT323 (wrapped to the paper, coverage thresholded so nothing anti-aliases). The close-up canvas is rebuilt when the ambient, `notesVersion` or the font's arrival changes. With a board close-up the panel stops listing the notes, since they are readable on the cork.

**Props** (`src/render/props.js`) are painted; this module only knows where they are (`PROPS`/`HOTSPOTS` from `META`) and draws what changes: notes on the cork (a scrap of paper at unit `u`, scribbled lines on the scene, legible text on a close-up), snow caps, sun shadows, the lantern's night glow. Redrawn only when `sunSide`, `groundSnow`, or `state.notesVersion` changes; bump `notesVersion` after mutating `state.notes`.

**UI** (`src/ui.js`): hover captions, click-to-zoom (`VIEWS` from `META`), HTML panels (`PANELS`, placeholder text), the debug panel (`D`), the status line (the tag line is 'a place, sort of.  liminally MSLA, MT, USA, EARTH.', then the time, temperature and weather; its capitals are its own, `#status` is exempt from the caption's lowercase). The canvas is CSS-scaled by `--s`; UI sizes are multiples of `--u`, which equals `--s` on a desktop and is floored at 0.8 on touch screens so a phone can read the captions. Keyboard events from the note field never reach the scene. Over a close-up on a touch screen or a short window (`COMPACT` media query) the panel folds to its buttons, a strip on the board's top rail, so the cork stays readable; the compose form unfolds it. When the scene is shown smaller than its pixels the canvas uses smooth scaling (`image-rendering: auto`, set in `fitStage`), because nearest-neighbor downscaling drops rows of the 4x4 Bayer pattern and turns every dither into blotches; crisp scaling only when shown larger. The screenshot tool renders at native size and never shows this, so judge dither on a real window. Desktop first; phones get readable UI, tap-to-enter and tap-to-leave, and a rotate hint in portrait, but a real landscape layout is a later job.
